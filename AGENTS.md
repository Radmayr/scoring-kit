# Инструкция для ИИ-агента в этом репозитории

scoring-kit — фабрика Airflow DAG'ов для батч-скоринга: из `pipeline.yaml` она генерирует
самодостаточный `.py` DAG. Архитектуру и логику фабрики ведёт один владелец; правки вносятся
согласованно, потому что на коде держатся рабочие процессы скоринга.

## Что можно менять самостоятельно

- Инфраструктуру запуска: `.gitlab-ci.yml`, образы, зеркала pip, переменные окружения, установку `mlc`.
- Передачу инфраструктурных параметров в `scoring_kit/publish.py` (адреса, флаги `mlc`), если без этого
  не работает выкладка. Такая правка идёт отдельным коммитом с объяснением причины и с тестом.
- Опечатки и уточнения в документации.

## Что менять нельзя без согласования с владельцем

- `scoring_kit/spec.py` (схема конфига), `recipes.py`, `blocks.py`, `codegen.py`, `render.py` (сборка DAG'ов).
- `scoring_kit/runtime.py`, `predictors.py`, `bundle.py`: код, который исполняется в подах и внутри
  упакованных моделей. Любая правка здесь меняет скоры.
- `scoring_kit/web/constructor.html`: логика формы и отправки в GitLab.
- Тесты: нельзя править или удалять тест, чтобы он «позеленел». Красный тест — это сигнал владельцу.

Если для запуска всё же пришлось тронуть что-то из этого списка: минимальная правка, отдельный коммит,
в сообщении — что сломалось, почему правка здесь и как проверено. Владелец потом решит, оставить
её или сделать иначе.

## Правила кода

- Всё, что попадает в сгенерированный DAG, самодостаточно: импорты внутри функций, никаких ссылок на
  пакет `scoring_kit` (в общий Airflow его не установить). Это проверяют тесты.
- Пакет `tnotifier` не импортировать: он завершает процесс при импорте.
- Тестовый и боевой инстансы пишут в один Greenplum. На тестовый инстанс уходят только теневые
  версии процессов (`shadow: true`, суффикс `_shadow`). Не обходить это правило.
- Реальные адреса, имена таблиц и ключи в этот репозиторий не добавлять: они живут в scoring-pipelines.

## Как проверять

```bash
pip install -e ".[dev]"
pytest -q                       # все тесты должны проходить; часть требует node
```

Перед коммитом: `pytest -q` зелёный. Версия в `pyproject.toml` и тег меняются только владельцем.

## Сообщения коммитов

Одна строка по-русски: область и суть, например `CI: образ Python из docker-hosted` или
`publish: endpoint из environments.yaml`. Инфраструктурные правки и правки кода фабрики — разными коммитами.
